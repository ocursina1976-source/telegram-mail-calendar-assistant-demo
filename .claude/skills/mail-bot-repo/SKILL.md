# Репозиторий telegram-mail-calendar-assistant (07_Почта)

Это инструкция для того, кто обслуживает и развивает проект. Правила самого бота (как отвечать в Telegram, запреты) лежат в `CLAUDE.md` и этим навыком не заменяются. Если сообщение пришло из Telegram, действуют правила `CLAUDE.md`, а не этот файл.

Перед работой прочитай `README.md` в корне: там устройство, типовые операции и «известные грабли». Не пересказывай его Ольге и не переспрашивай про уже настроенное.

## Структура

| Путь | Назначение | Публикуется |
|---|---|---|
| `CLAUDE.md` | Правила поведения бота | да |
| `.claude/settings.json` | Deny на изменение Google-календаря, включение плагина Telegram только здесь | да |
| `.claude/skills/` | Навыки проекта (этот файл) | да |
| `yandex-mcp/server.py` | MCP-сервер (FastMCP): Яндекс.Почта по IMAP, Яндекс.Календарь по CalDAV | да |
| `yandex-mcp/requirements.txt` | Зависимости, `mcp<2` закреплено намеренно | да |
| `yandex-mcp/.env.example` | Шаблон секретов | да |
| `yandex-mcp/.env`, `.venv/`, `__pycache__/`, `*.bak` | Секреты и локальное | **нет** |
| `scripts/digest.ps1`, `scripts/prompts/*.txt`, `scripts/digest-settings.json` | Регулярные сводки (morning, noon, evening) | да |
| `scripts/digest.log` | Лог сводок | нет |
| `backup/` | Резервная копия Google-календаря | **нет** |
| `README.md` (корень) | Техническая документация для обслуживающего | да |
| `.github/README.md` | Витрина проекта для GitHub | да |
| `images/` | Картинки для `.github/README.md` | да |

Инструменты MCP: `accounts_list`, `mail_list_folders`, `mail_list_unread`, `mail_search`, `mail_read`, `mail_create_draft`, `cal_list_calendars`, `cal_list_events`, `cal_create_event`. Инструментов отправки, удаления, переноса писем и пометки «прочитано» нет намеренно. Не добавляй их без прямой просьбы Ольги.

## Запуск и проверка

- Бот запускает Ольга ярлыком на рабочем столе (`claude --model claude-sonnet-5-5 --channels plugin:telegram@claude-plugins-official`, рабочая папка — корень проекта). Сам не запускай и не останавливай процессы бота без просьбы.
- Регистрация MCP: `claude mcp list` из корня проекта; `yandex` и `claude.ai Google Calendar` должны быть Connected.
- Проверка кода без Telegram: `yandex-mcp\.venv\Scripts\python.exe -I -m py_compile yandex-mcp\server.py` (синтаксис). Для проверки подключений запусти тестовый скрипт на `yandex-mcp\.venv\Scripts\python.exe`, который импортирует `server` и печатает только счётчики (число папок, писем, событий).
- «Бот молчит»: `Get-CimInstance Win32_Process -Filter "Name='bun.exe'"` — должен быть один процесс `server.ts`. Если процессов несколько, причина в лишних опросчиках Telegram (раздел «Известные грабли» в `README.md`).
- Сводки: смотри хвост `scripts\digest.log`; запуск вручную `scripts\digest.ps1 -Mode <morning|noon|evening>` отправляет сообщение в реальный чат, поэтому только по просьбе Ольги.

## Внесение изменений

1. Сначала посмотри, что менялось: `git status`, `git diff`.
2. Перед правкой `server.py` сделай копию `server.py.bak` (она в `.gitignore`).
3. Правь минимально, в стиле файла (русские комментарии, имена как в соседнем коде).
4. Проверь синтаксис (см. выше) и, если менялась работа с IMAP или CalDAV, прогон тестовым скриптом со счётчиками.
5. Изменения `server.py`, `CLAUDE.md` и `settings.json` вступают в силу только после перезапуска бота (`/exit`, затем ярлык). Скажи об этом Ольге.
6. Не включай плагин Telegram глобально и не трогай `~\.claude\settings.json`.
7. Версию `mcp` не повышай: в 2.x переименован FastMCP.

Границы, которые нельзя нарушать без явного разрешения Ольги: не отправлять и не удалять письма, не менять и не удалять существующие события, не устанавливать ПО, не менять настройки ПК, файлы удалять только в корзину.

## Секреты

- Не читай и не показывай `yandex-mcp\.env`, `%USERPROFILE%\.claude\channels\telegram\.env`, `access.json`.
- Токен бота, пароли приложений и адреса из писем не вставляй в README, скриншоты, логи и коммиты.
- В `.env.example` только пустые значения или заглушки.

## Обновление README

Два файла с разной ролью, держи их согласованными:
- `README.md` (корень) — для обслуживающего: операции, грабли. Правь при каждой смене эксплуатации.
- `.github/README.md` — витрина для GitHub: проблема, возможности, безопасность, архитектура, установка, известные проблемы, планы.

Что синхронизировать при изменениях:
- новые или убранные инструменты MCP → «Возможности», «Безопасность», «Архитектура»;
- новая грабля → «Известные проблемы» в обоих файлах;
- смена расписания сводок → таблица «Регулярные сводки» и раздел в корневом README;
- новые файлы и папки → таблица «Структура репозитория» (в ней пока нет `images/` и `.claude/skills/`).

Картинки:
- лежат в `images/` в корне репозитория; ссылка из `.github/README.md` относительная: `../images/<имя>` (путь считается от папки `.github/`);
- текущие имена: `1000088627.png` (логотип), `1000088631.jpg` (скрин Telegram), `1000088632.png` (скрин Claude Code); при переименовании нужно переименовать и на GitHub, и в ссылках;
- у каждой картинки заполняй `alt`;
- на скриншотах не должно быть токена, паролей и лишних личных данных.

## Проверка перед публикацией

1. `git status` и `git diff --stat`: нет ли лишнего.
2. Секреты: `git ls-files` не содержит `.env`, `.venv`, `backup/`, `*.bak`, `digest.log`. Поиск по отслеживаемым файлам строк вроде `password`, `token`, `@yandex.ru`, `app_password` с проверкой, что это только шаблоны и описания.
3. `.gitignore` покрывает `.env`, `.venv/`, `__pycache__/`, `backup/`, `scripts/digest.log`, `*.bak`, `.claude/settings.local.json`.
4. `server.py` компилируется, `requirements.txt` актуален (`pip freeze` сравнить с реально используемыми: `mcp`, `imapclient`, `caldav`, `icalendar`, `python-dotenv`, `tzdata`).
5. README: ссылки на файлы и картинки существуют (проверь, что каждый путь из `../images/...` есть на диске), оглавление совпадает с заголовками, нет устаревших фактов (расписание, названия инструментов).
6. Скриншоты без чувствительных данных.

Коммит и push делай только по просьбе Ольги. Remote: `origin` на GitHub `ocursina1976-source/telegram-mail-calendar-assistant-demo`. Сообщения коммитов на русском, по сути изменения. Ветку и историю не переписывай, `--force` не используй.
